防御页面开发说明

1. 页面目标

新增“防御”页面，用于展示危险命令策略管理的 UI 原型。
该页面当前定位为纯 demo 页面，不接真实防护引擎，不做规则持久化，不执行任何拦截逻辑。

页面目的主要是：

- 预演危险命令策略管理界面
- 演示未来 AI 命令审查/阻断的产品形态
- 给后续真正的策略引擎实现提供视觉和交互草图


2. 当前定位

当前防御页面是静态 UI 页面，仅用于展示，不具备以下能力：

- 不会真正拦截命令
- 不会真正写入规则
- 不会调用后端接口保存
- 不会影响当前 AI 执行行为

换句话说，目前它只是一个“策略管理页面的演示稿”。


3. 页面主要场景

页面假设未来 AI 在执行命令前，需要根据危险命令策略做处理，例如：

- 提示
- 人工确认
- 直接阻止

主要关注对象包括：

3.1 Oracle 数据库维护相关命令

- truncate table
- drop table
- delete from
- update ... without where

3.2 Linux / 文件系统相关命令

- rm -rf
- shutdown -h now
- reboot


4. 页面实现文件

页面主文件：

E:\nanobot-main\nanobot-webui-main\web\src\pages\Defense.tsx

该页面最初是空白占位页，现已改造成静态策略管理 dashboard。


5. 数据来源方式

当前防御页面不走后端接口，不读取数据库，也不读取配置文件。
页面中的规则全部是前端静态数组写死，用于 UI 设计展示。

当前静态规则定义在：

Defense.tsx

内部的：

RULES

数组中。


6. 当前静态规则结构

当前每条规则包含以下字段：

- command
- category
- severity
- mode
- scope
- note

字段说明：

6.1 command

危险命令内容，例如：

- truncate table
- rm -rf

6.2 category

命令分类，目前分为：

- oracle
- linux
- filesystem

6.3 severity

风险等级，目前分为：

- high
- critical

6.4 mode

处理方式，目前分为：

- warn
- block

6.5 scope

规则适用范围，例如：

- SQL
- Shell

6.6 note

备注说明，用于提示该命令为什么危险。


7. 页面结构设计

整体风格与系统现有页面保持一致，采用：

- 顶部统计卡片
- 中部说明 banner
- 搜索过滤输入框
- 下方规则表格

保证视觉上与 Dashboard、Host、Audit 等页面风格统一。


8. 顶部摘要卡片

当前顶部设计了 3 个摘要卡片：

- 规则总数
- 阻止规则
- 提示规则

作用：

- 提升 dashboard 感
- 快速展示策略概况
- 让用户对规则规模和分布有第一眼认知


9. 中部说明区域

页面中间设计了一条 banner，明确说明：

- 当前是静态 demo
- 主要针对 Oracle 和 Linux 危险命令
- 不会实际执行防御逻辑

这样可避免用户误以为系统已经具备真正的命令阻断能力。


10. 关键字过滤

页面中增加了一个过滤输入框。

当前支持按以下字段进行静态过滤：

- command
- category
- severity
- mode
- scope
- note

说明：

- 这是纯前端过滤
- 不涉及后端检索
- 用于 demo 页面提升可用性和交互感


11. 规则表格设计

表格列包括：

- 危险命令
- 分类
- 等级
- 处理方式
- 适用范围
- 备注
- 操作

其中“操作”列当前放了静态按钮：

- 修改
- 删除

页面右上角还放了：

- 新增规则
- 编辑策略

这些按钮目前都是静态展示，不绑定真实逻辑。


12. 风险视觉设计

页面对不同信息做了颜色区分，增强可读性：

12.1 分类

- Oracle
- Linux
- 文件系统

分别使用不同 badge 风格。

12.2 风险等级

- high
- critical

critical 的风险更高，颜色更强烈。

12.3 处理方式

- warn
- block

其中 block 以更醒目的方式展示，强调阻止含义。


13. 当前静态规则内容

当前已内置的 demo 规则包括：

- truncate table
- drop table
- delete from
- update ... without where
- rm -rf
- shutdown -h now
- reboot

这些命令主要覆盖：

- Oracle 高风险 DDL / DML
- Linux 高风险系统命令
- 文件系统高风险删除操作

15. 当前实现特点

当前防御页面具备以下特点：

- 风格与其它页面统一
- 具备 dashboard 摘要卡片
- 具备危险命令管理表格
- 具备关键字过滤交互
- 具备新增/编辑/删除按钮样式
- 适合用于产品演示和后续交互设计延伸


16. 当前没有实现的内容

当前版本未实现：

- 后端规则接口
- 规则持久化
- 规则编辑弹窗
- 规则新增表单
- 真正的命令审查逻辑
- 真正的 AI 执行前拦截
- 按 workspace / agent / user 区分规则
- 命中规则后的提示或阻止动作


17. 后续可扩展方向

后续如果继续开发，可考虑：

- 增加后端 defense 配置接口
- 规则保存到 json / db
- 增加新增/编辑弹窗
- 支持正则命令匹配
- 支持命令白名单 / 黑名单
- 支持按命令类型区分处理策略
- 支持“提示后允许执行”
- 支持“阻止并记录审计”
- 与审计页面联动，记录命中防御规则的事件
