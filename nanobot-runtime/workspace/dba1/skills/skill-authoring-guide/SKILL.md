# Skill Authoring Guide

本 Skill 用于指导 AI 在当前工作区中自行编写、改写和规范化 `SKILL.md` 文件，确保结构一致、可注入、可维护、可执行。

## 与其它 Skill / Tools 协同

- 先读取同目录已有 Skill，优先复用已验证风格与章节结构
- 涉及主机执行、数据库执行等场景时，引用对应领域 Skill 的术语和动作边界
- 写入前先确认目标路径与命名，避免重复创建近似同名 Skill

## 标准执行策略

- 发现同名或高相似 Skill 时，必须先询问用户“新增还是覆盖”
- 所有 Skill 必须包含 frontmatter：`name`、`description`
- `description` 必须同时说明“做什么 + 何时调用”
- 章节采用统一骨架，避免纯手册式堆命令
- 输出必须可执行：步骤清晰、命令可直接复制、边界明确

## 何时使用

- 用户要求“写一个 Skill / 新增 Skill”
- 用户要求“优化现有 Skill 格式”
- 用户要求“统一目录下 Skill 风格”
- 用户要求“让 AI 自动按规范编写 Skill”

## 输入与识别规则

- 先识别目标目录（默认：当前 workspace 的 `skills/`）
- 先识别任务类型：
  - 新建 Skill
  - 重构已有 Skill
  - 仅补充 frontmatter 或章节
- 先识别领域：
  - 运维执行类
  - 数据库类
  - 通用流程类
- 生成 `name` 规则：
  - 使用小写英文与连字符
  - 避免下划线与大小写混用
  - 与现有 Skill 不重名

## Skill 文件硬性规范

1. 路径规范
   - 目录：`<workspace>/skills/<skill-name>/`
   - 文件：`<workspace>/skills/<skill-name>/SKILL.md`

2. frontmatter 规范
   - 必须位于文件顶部
   - 必填字段：
     - `name: <skill-name>`
     - `description: <一句话说明做什么+何时调用>`

3. 正文章节规范
   - 建议使用以下固定章节：
     - `# <Skill Title>`
     - `## 与其它 Skill / Tools 协同`
     - `## 标准执行策略`
     - `## 何时使用`
     - `## 输入与识别规则`
     - `## 执行流程`
     - `## 安全与幂等要求`
     - `## 输出要求`

## 编写流程

1. 读取参考 Skill
   - 至少读取一个同目录高质量 Skill
   - 抽取其章节骨架与语气风格

2. 决定“新建 or 改写”
   - 发现同名或高相似 Skill 已存在时，先询问用户选择：
     - 新增：创建新目录并使用差异化命名
     - 覆盖：在原 Skill 上改写并保留关键领域规则
   - 仅在确实缺失能力时新建目录

3. 生成 frontmatter
   - `name` 与目录名保持一致
   - `description` 控制在简洁单句内，明确触发条件

4. 生成正文
   - 先写策略与边界，再写步骤与命令
   - 命令尽量给最小可执行集合，不堆过长资料

5. 自检
   - 是否有 frontmatter
   - 是否有“何时使用”
   - 是否有“安全与幂等要求”
   - 是否有“输出要求”
   - 是否与现有 Skill 重复或冲突

## 输出模板

```markdown
---
name: <skill-name>
description: <做什么。用户在什么场景下应调用该 Skill。>
---

# <Skill Title>

<一句话说明目标与范围>

## 与其它 Skill / Tools 协同
- <协同规则1>
- <协同规则2>

## 标准执行策略
- <策略1>
- <策略2>

## 何时使用
- <触发场景1>
- <触发场景2>

## 输入与识别规则
- <输入项1>
- <识别项2>

## 执行流程
1. <步骤1>
2. <步骤2>
3. <步骤3>

## 安全与幂等要求
- <安全规则1>
- <幂等规则2>

## 输出要求
- <输出项1>
- <失败输出项2>
```

## 安全与幂等要求

- 禁止生成含密钥、密码明文示例的最终内容
- 涉及删除、覆盖、停机动作时必须要求前置确认
- 同一任务重复执行时必须可识别“已完成”并避免重复破坏
- 禁止省略失败分支，必须保留错误处理与回退建议

## 输出要求

- 明确给出：新增/修改的 Skill 路径
- 明确给出：frontmatter 是否齐全
- 明确给出：章节是否完整
- 若改写了旧 Skill，说明保留了哪些原有领域规则
