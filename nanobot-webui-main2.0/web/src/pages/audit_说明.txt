审计页面开发说明

1. 页面目标

新增“审计”页面，用于展示当前 workspace 下 sessions 目录中的会话文件内容。
该页面当前定位为 demo 审计 dashboard，不做复杂权限流转、不做真实审计检索引擎、不做导出与归档，仅用于：

- 展示当前 workspace 中的会话文件
- 预览每个会话文件的最近内容
- 形成一个适合后续扩展的审计表格界面


2. 数据来源

审计页面的数据来源不是前端写死，而是每次进入页面时，动态读取当前启动 WebUI 时指定 workspace 下的：

sessions

目录。

例如当前测试 workspace 是：

E:\nanobot-main\dba1

则实际读取目录是：

E:\nanobot-main\dba1\sessions


3. 当前 sessions 目录结构分析

当前测试环境中，sessions 目录里并不是普通 .json 文件，而是多份 .jsonl 文件，例如：

- qq_EBC761E75F988019ABF0C06C7A5DD1E3.jsonl
- web_f5e58642-96f3-4735-bb4d-42734f74d098_3ae9772c.jsonl
- web_f5e58642-96f3-4735-bb4d-42734f74d098_ec4e5ecd.jsonl

这些文件的特点：

- 每一行都是一个 JSON 对象
- 第一行通常是 metadata
- 后续每行可能是：
  - user
  - assistant
  - tool
  - metadata


4. 当前会话文件内容结构

常见行示例：

metadata 行：

{
  "_type": "metadata",
  "key": "web:...",
  "created_at": "...",
  "updated_at": "..."
}

普通消息行：

{
  "role": "user",
  "content": "hi",
  "timestamp": "..."
}

工具调用行：

{
  "role": "assistant",
  "content": "",
  "tool_calls": [...]
}

工具结果行：

{
  "role": "tool",
  "name": "web_fetch",
  "content": "..."
}


5. 后端实现

为了避免前端直接拼路径读取 workspace 文件，新增了一个专用后端接口。

后端文件：

E:\nanobot-main\nanobot-webui-main\webui\api\routes\audit.py

接口：

GET /api/audit/sessions

接口实现逻辑：

- 从当前运行时配置中读取 workspace
- 定位 workspace/sessions 目录
- 扫描全部 *.jsonl 文件
- 按文件修改时间倒序处理
- 每个文件只取最后 20 行
- 逐行解析 JSON
- 提取以下信息返回给前端：
  - file_name
  - session_type
  - session_key
  - created_at
  - updated_at
  - line_count
  - records

其中 records 内部会统一整理为：

- line_number
- role
- timestamp
- summary
- raw


6. 为什么只取最后 20 行

当前页面是 demo 展示页面，不需要完整载入所有历史内容。
只取最后 20 行的目的：

- 保持页面轻量
- 避免前端一次性加载大量历史消息
- 更符合“审计预览”而不是“全文回放”的定位

如果后续需要做完整审计能力，可以再扩展：

- 分页
- 全文搜索
- 文件级展开
- 时间范围过滤
- 导出功能


7. 前端数据读取方式

前端新增 hook：

E:\nanobot-main\nanobot-webui-main\web\src\hooks\useAuditSessions.ts

作用：

- 请求 /api/audit/sessions
- 获取当前 workspace 的会话审计数据
- 页面每次重新进入时重新读取

关键配置：

- staleTime: 0
- refetchOnMount: "always"

这意味着：

- 审计页面每次打开时都会重新读取当前 sessions 目录
- 不长期依赖缓存

页面主文件：

E:\nanobot-main\nanobot-webui-main\web\src\pages\Audit.tsx

9. 页面结构设计

整体视觉风格参考系统已有页面，如 Dashboard、Host 页面，保持：

- 顶部统计卡片
- 中部筛选区域
- 下方卡片式内容区
- 表格化展示


10. 页面结构拆分

10.1 顶部统计卡片

当前顶部设计了 4 个摘要卡片：

- 会话文件
- 审计记录
- Web 会话
- 外部会话

这些卡片主要用于增强 dashboard 感，不依赖复杂逻辑。


10.2 中部说明与过滤区域

页面中间展示：

- 当前 sessions 目录路径
- 一个关键字过滤 input

关键字过滤支持匹配：

- 文件名
- session_key
- session_type
- role
- timestamp
- summary


10.3 文件级表格展示区

每个 session 文件使用一个 Card 展示。

卡片中包含：

- 文件名
- session_key 或 session_type
- 创建时间
- 更新时间
- 总行数
- 最近 20 行的表格


11. 表格字段设计

每个文件内部表格当前展示：

- 行号
- 角色
- 时间
- 内容摘要

说明：

- 不直接完整展开 raw JSON
- 当前只展示摘要，更适合审计首页视图
- 后续若需要可增加“查看原始 JSON”功能


12. 内容摘要生成方式

后端会对每条记录生成 summary：

- 普通消息：取 content
- tool_calls：显示调用的工具名摘要
- tool 记录：显示 tool name + content 摘要
- 异常 JSON：标记为 invalid

同时会进行长度截断和空白压缩，以保证表格整洁。


13. 角色颜色设计

前端对不同 role 做了简单视觉区分：

- user
- assistant
- tool
- metadata
- invalid

目的是提升审计页面可读性，让用户能快速看出一段记录的来源。

15. 当前实现特点

当前审计页面具备以下特点：

- 每次进入页面动态读取当前 workspace/sessions
- 支持多文件展示
- 支持关键字过滤
- 每个文件只展示最近 20 行
- 视觉风格与系统其它页面保持一致
- 适合作为后续审计系统的首页 demo
