添加新页面通用实现说明

1. 目标定义

在开始写代码前，先明确新页面的目标。

至少要先确认：

- 页面名称
- 页面用途
- 目标用户
- 是否需要管理员权限
- 数据来源是前端静态数据还是后端接口
- 是否需要写回 workspace 文件
- 是否需要多语言

如果这些问题不先明确，后面很容易出现页面结构反复调整。


2. 页面类型判断

通常新增页面会落在以下几类之一：

- 纯展示页
- 配置编辑页
- 文件查看/编辑页
- 表格/列表页
- 仪表板页
- 混合型页面

不同类型决定后续实现方式：

- 纯展示页：前端组件为主
- 配置编辑页：需要表单状态、保存逻辑、校验逻辑
- 文件编辑页：需要读取文件、编辑、保存、同步提示
- 列表页：需要筛选、排序、空状态
- 仪表板页：需要统计卡片、摘要、可视化布局


3. 确认数据来源

新增页面前，先明确数据从哪里来。

常见来源：

- 当前 workspace 下的文件
- 运行时配置
- WebUI 后端接口
- 本地静态常量

推荐原则：

- 前端不要直接拼接复杂路径做读取逻辑
- 只要涉及 workspace 扫描、目录遍历、文件解析，优先放到后端接口里做
- 前端尽量只负责请求、展示、编辑交互


4. 创建页面组件

页面主文件通常放在：

E:\nanobot-main\nanobot-webui-main\web\src\pages

新增页面时，一般新建：

- Xxx.tsx

建议结构：

- 顶部标题区
- 页面说明区
- 主要内容区
- 加载态
- 空状态
- 错误提示

页面风格尽量复用现有系统组件，如：

- Card
- Button
- Input / Textarea
- Badge
- Table
- Skeleton

这样能保持整体视觉一致。


5. 接入路由

前端路由文件：

E:\nanobot-main\nanobot-webui-main\web\src\App.tsx

新增页面通常需要做两件事：

- 新增 lazy import
- 新增 Route

例如常见流程：

- import 新页面组件
- 在受保护路由区增加 path
- 如果页面只允许管理员访问，则包在 AdminRoute 中

注意：

- 懒加载返回类型要合法
- 不要写出导致 TypeScript 类型不匹配的兜底组件


6. 接入导航

如果页面需要在界面上可访问，还要补导航入口。

常见位置：

- Sidebar.tsx
- MobileBottomTabs.tsx

需要确认：

- 页面放在哪个分组
- 桌面端是否显示
- 移动端是否显示
- 是否受权限控制

如果只是临时页面，也可以只挂路由，不挂导航。


7. 接入多语言

如果页面面向正式使用，建议同步接入 i18n。

语言文件目录：

E:\nanobot-main\nanobot-webui-main\web\src\i18n\locales

通常需要补：

- nav.xxx
- xxx.title
- xxx.subtitle
- xxx.empty
- xxx.loading
- xxx.save
- xxx.error

推荐至少同步这些语言：

- zh.json
- en.json
- zh-TW.json
- ja.json
- ko.json
- de.json
- fr.json

页面内统一用 t("xxx.key")，不要把文案硬编码在组件里。


8. 需要后端时的实现方式

如果页面涉及 workspace 文件、运行配置、系统状态、目录扫描、批量数据整理，建议新增后端接口。

后端常见位置：

E:\nanobot-main\nanobot-webui-main\webui\api\routes

实现步骤通常是：

- 新增 route 文件或扩展已有 route
- 在 server.py 中注册路由
- 定义返回结构
- 做基本异常处理
- 让前端通过统一 api 客户端访问

不要把复杂业务逻辑堆到页面组件里。


9. 需要前端 hook 时的实现方式

如果页面需要请求后端，推荐把请求逻辑收敛到 hook。

常见目录：

E:\nanobot-main\nanobot-webui-main\web\src\hooks

常见做法：

- 新增 useXxx.ts
- 在 hook 中封装请求
- 统一处理缓存策略
- 组件只消费数据和状态

例如需要关注：

- isLoading
- error
- refetch
- staleTime
- refetchOnMount

这样页面组件会更干净。


10. 页面布局建议

通用布局建议如下：

10.1 标题区

通常包含：

- title
- subtitle
- 操作按钮

10.2 内容区

根据页面类型选择：

- 左右分栏
- 上下分区
- 卡片网格
- 表格列表

10.3 状态区

建议统一处理：

- loading
- empty
- error
- saving
- saved


11. 文件编辑类页面的通用步骤

如果页面是查看或维护 workspace 文件，通常流程是：

- 后端提供读取接口
- 前端读取文件内容
- 页面展示当前文件路径
- 用户编辑内容
- 用户点击保存
- 保存成功后给出同步提示

额外建议：

- 增加 dirty 状态
- 防止覆盖未保存内容
- 保存后刷新数据
- 提示文件来源


12. 图片或附件类页面的通用步骤

如果页面需要展示 workspace 内图片或附件，建议：

- 优先读取 workspace 文件
- 找不到时回退到默认资源
- 对加载失败做 onError 兜底
- 注意 Blob URL 清理，避免内存泄漏
- 样式上优先保持原始比例


13. 权限控制

需要明确页面是否只允许管理员访问。

常见做法：

- 普通登录可见：PrivateRoute
- 管理员可见：AdminRoute

不要只在导航上隐藏，不在路由层限制。


14. 联动文件清单

一个完整的新页面，常见会涉及这些文件：

前端：

- web/src/pages/Xxx.tsx
- web/src/App.tsx
- web/src/components/layout/Sidebar.tsx
- web/src/components/layout/MobileBottomTabs.tsx
- web/src/hooks/useXxx.ts

后端（如需要）：

- webui/api/routes/xxx.py
- webui/api/server.py

多语言：

- web/src/i18n/locales/zh.json
- web/src/i18n/locales/en.json
- web/src/i18n/locales/zh-TW.json
- web/src/i18n/locales/ja.json
- web/src/i18n/locales/ko.json
- web/src/i18n/locales/de.json
- web/src/i18n/locales/fr.json


15. 实施顺序建议

推荐按这个顺序开发：

1. 明确页面目标和权限
2. 确认数据来源
3. 先做后端接口或 hook
4. 再做页面主组件
5. 接入路由
6. 接入导航
7. 接入多语言
8. 处理 loading / empty / error
9. 本地构建验证
10. 补充说明文档

这样返工最少。


16. 验证步骤

新增页面完成后，至少检查：

- 路由能否访问
- 导航是否出现
- 页面标题是否正确
- 数据是否正确加载
- 空状态是否正常
- 保存逻辑是否正常
- 多语言是否正常切换
- 移动端布局是否可用
- npm run build 是否通过
- 相关文件是否无诊断错误


17. 常见问题

常见问题包括：

- 路由加了但导航没加
- 导航加了但没有权限控制
- 文案写死，未接入 i18n
- 页面直接写请求，逻辑过重
- workspace 路径处理放在前端
- 缺少加载态和空状态
- 懒加载写法导致 TypeScript 报错
- 保存后 UI 没有同步刷新


18. 推荐原则总结

新增页面时，尽量遵守以下原则：

- 页面组件只负责展示和交互
- 数据读取尽量通过 hook
- 文件和目录处理尽量放后端
- 文案统一走 i18n
- 风格统一复用现有 UI 组件
- 权限控制放在路由层
- 提交前至少完成一次构建验证


19. 建议的交付结果

一个完整可用的新页面，理想上应当具备：

- 可访问路由
- 可见导航
- 正常数据来源
- 清晰页面结构
- 基本状态处理
- 多语言支持
- 权限控制
- 本地构建通过
- 有对应说明文档
